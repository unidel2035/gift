# Сессия → PM воркспейса trytofly

Разбивает всё, что сделано в этой сессии, на PM-задачи воркспейса **trytofly** —
по контексту задачи: крупная работа → эпик, шаги/темы → подзадачи.

## Политика

Та же, что у plan-to-pm (см. `.claude/skills/plan-to-pm/SKILL.md`, раздел
«Политика»): одна работа — одна задача; метки 2–4 при создании каждого;
`done` — переходом `pm_update_issue`; estimate/due_date не выдумывать;
существующие задачи не трогать; дедуп по названию эпика перед созданием.

## Шаги

1. **Воркспейс:** `switch_workspace("trytofly")` — всегда он, независимо от
   активного.
2. **Собери контекст сессии:** `git log --oneline` коммиты сессии, правленные
   файлы (`git diff --name-only`), темы разговоров. Сгруппируй по контекстам
   задач: один контекст (одна фича/проект/инцидент) — один эпик; внутри —
   подзадачи по шагам.
3. **Дедуп:** `pm_list_issues` поиском по названиям эпиков. Существует — покажи
   номер и предложи дополнить его новыми подзадачами вместо создания дубля.
4. **Черновик:** для каждого контекста — эпик (title + «Зачем:») и дети
   («что сделано» + «Зачем:», метки 2–4). Закрытые работы — со статусом done
   ПОСЛЕ создания. Покажи весь черновик и жди «да».
5. **Создание:** эпики и дети через `pm_create_issue` (дети с `parent_id`),
   завершённые подзадачи — `pm_update_issue {status:"done"}`. Незавершённое —
   оставь открытым (todo) и скажи об этом явно.

## Зачем

Отчёт сессии «всё в одной простыне» не читается и не считается. Разбивка по
контекстам в PM trytofly даёт Д Г видимость хода работ без запросов статуса.
