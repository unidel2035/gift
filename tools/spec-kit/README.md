# spec-kit — исполняемые спецификации для компонентов

Один общий инструмент проверок для всей команды. Требование — не абзац в README,
а маленькая программа: сама запускается, падает, если условие нарушено.

## Установка (2 минуты, без зависимостей)

```bash
# скопируй в свой репозиторий:
mkdir -p tools/spec
cp SpecRunner.mjs spec.mjs spec.hello.js tools/spec/
# пример спеки — в конце этого README

# package.json:
"scripts": { "spec": "node tools/spec/spec.mjs" }

npm run spec
```

Требование: Node ≥ 18. Больше ничего — ни npm-пакетов, ни сервисов.

(Если проект не ESM — добавь `"type": "module"` в package.json, иначе Node
предупредит о репарсинге. Работает и без него, просто с warning.)

## Как выглядит спека

Файл `spec.<module>.js` в `tools/spec/` (все `spec.*.js` подхватываются автоматически):

```js
export const meta = { module: 'payments', description: 'что сторожит модуль', tags: [] }

export const specs = [
  {
    name: 'invoice-rounding',
    clause: 'PAY-001',              // стабильный id: на него ссылаются задачи и коммиты
    given: 'сумма 10.005',
    when: 'считаю итог счёта',
    then: 'округление банковское: 10.00',
    falsifier: 'итог 10.01 или NaN', // ОБЯЗАТЕЛЬНО — без него спека не валидна
    timeout: 5000,
    async run(ctx) {
      const r = await ctx.exec('node -e "console.log(round(10.005))"', 5000)
      ctx.assert(r.code === 0, `упало: ${r.stderr}`)
      ctx.assert(r.stdout.trim() === '10.00', `получили ${r.stdout.trim()}`)
    },
  },
]

## Правила формата

| Поле | Обязанность |
|---|---|
| `name` | короткое имя латиницей — id в отчётах |
| `clause` | стабильный id (`PAY-001`). Опубликовал — не меняй: на него ссылаются задачи |
| `given/when/then` | требование человеческим языком |
| `falsifier` | **обязателен при clause**: при каком наблюдении требование опровергнуто. Спека без него — не контракт, прогон падает |
| `run(ctx)` | сама проверка |

Клауза устарела? Не удаляй — поставь `supersededBy: 'PAY-002'` в новой. Старые ссылки продолжат резолвиться, история не рвётся.

## Команды

```bash
npm run spec                 # все модули
node tools/spec/spec.mjs payments          # один модуль
node tools/spec/spec.mjs payments --json   # машиночитаемо — для CI и агентов
```

Exit code: `0` = GREEN, `1` = RED. В CI вешается одной строкой.

## Что умеет ctx внутри run()

```js
ctx.assert(cond, msg)                 // обычная проверка
const r = await ctx.exec(cmd, ms)     // любая команда: { code, stdout, stderr }
// r.code === 0, r.stdout.includes(...)
```

`ctx.exec` — главный инструмент: спека может гонять билды, curl, тесты, скрипты —
что угодно, что запускается из шелла репозитория.

## Зачем это (один абзац)

Агентские цепочки теперь длинные: 30 шагов по 95% надёжности завершаются в 21%
случаев, по 98% — в 54%. Весь выигрыш — в хвосте ошибок, который глазом не виден.
Единственная защита — среда, где шаг проверяется не «посмотрел — похоже», а
автоматически. Правило конвейера: цепочка агента длиннее 10 шагов не считается
выполненной, пока не прошла исполняемую спеку. Этот kit — тот же инструмент,
который уже сторожит 42 клаузы в дроновом конвейере, вырезанный в самодостаточный
пакет без зависимостей.

## Что НЕ входит (сознательно)

- LLM-судьи и адверсариальная верификация — в общем контуре; сюда не тащим.
- Генерация сценариев (property-based) — приживётся поверх позже тем же форматом.
