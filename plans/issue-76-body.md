## Улучшенное описание issue #76

## Проблема
Неясно, работает ли полный конвейер вопрошания (`voroshaniye-hook` → `gift-plan` → `gift-dev-loop` → PR) прямо внутри сессии Claude Code — без ручного запуска утилит. Пользователь не получает явной обратной связи о том, что его вопрошание зафиксировано, спланировано и передано в реализацию в рамках одной сессии.

## Контекст
Это фундаментальная проверка онтологического конвейера: хук `voroshaniye-hook.mjs` создаёт issue, но `gift-plan` и `gift-dev-loop` не запускаются автоматически после этого — нет замкнутого цикла внутри сессии.

## Ожидаемое поведение
- Вопрошание Дионисия → автоматически создаётся issue с `gift-ready`
- Claude в той же сессии видит новый issue, запускает `gift-plan`, получает `plan-approved`
- `gift-dev-loop --once` запускается и реализует план
- Весь цикл отражается в матрице W (Дионисий→_claude→_koinon)

## Технические детали
- `utils/voroshaniye-hook.mjs` — создаёт issue (работает)
- `utils/gift-plan.mjs` — планировщик (не вызывается автоматически после hook)
- `.claude/settings.json` SessionStart hook — проверяет `--pending`, но не реагирует на новые issues в сессии
- Нужен PostToolUse или новый хук после создания issue

## Критерии приёмки
- [ ] После вопрошания в сессии Claude автоматически видит созданный issue и запускает план
- [ ] Матрица W обновляется: Дионисий→_claude (direction) + _claude→Дионисий (plan)
- [ ] Пользователь получает сообщение: "вопрошание зафиксировано → issue #N → план создан"
